# Bank Soal Draft Duplicate Guard Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Mencegah duplikasi draft soal Bank Soal akibat POST create berulang, sekaligus menyediakan cleanup aman untuk data duplikat yang belum dipakai.

**Architecture:** Perbaikan dilakukan berlapis: frontend menahan submit ganda, backend menegakkan idempotency/fingerprint draft, dan cleanup data dilakukan terpisah setelah audit. SvelteKit tetap BFF/proxy saja; aturan bisnis anti-duplikat wajib berada di Go core-api. Tidak ada deploy/restart production tanpa persetujuan eksplisit.

**Tech Stack:** SvelteKit 2/Svelte 5, Go core-api, sqlc, PostgreSQL 16, PM2 runtime.

Root cause sementara:

1. `CreateCbtQuestion` selalu membuat UUID baru (`gen_random_uuid()`) sehingga setiap POST menjadi record baru.
2. Backend belum mengecek draft serupa milik author yang sama.
3. Frontend komposer memakai POST jika `editingId` kosong dan belum punya guard awal `if (composerBusy) return;`.
4. Offline/retry/Ctrl+S/klik cepat bisa mengirim create berulang; backend tidak punya idempotency key/fingerprint untuk membedakannya.

---

## Non-Negotiable Safety Rules

- Jangan deploy/restart production tanpa approval.
- Jangan hapus data production sebelum audit + backup + persetujuan.
- Jangan akses PostgreSQL dari SvelteKit; semua business rule tetap di core-api.
- Cleanup duplikat harus hanya menyasar draft yang belum dipakai paket/jawaban.
- Jangan mengubah/menghapus soal yang `package_count > 0` atau `answer_count > 0`.
- Jangan drop/rename kolom untuk solusi ini.

---

## Proposed Approach

1. Tambahkan guard frontend agar satu proses save komposer tidak bisa berjalan paralel.
2. Tambahkan deteksi duplicate draft di backend sebelum insert.
3. Buat query sqlc untuk mencari draft serupa memakai fingerprint normalisasi teks.
4. Jika duplicate draft ditemukan, return existing draft atau beri error 409 yang jelas. Rekomendasi: return existing draft untuk idempotency yang ramah UX.
5. Tambahkan test backend service/handler untuk create berulang.
6. Tambahkan test frontend helper/komponen jika memungkinkan agar `composerBusy` menahan double submit.
7. Siapkan SQL cleanup terpisah dan report-only dulu.

## Sprint 1: Backend Duplicate Draft Detection

### Task 1.1: Add sqlc query to find existing draft by fingerprint

**Objective:** Provide a typed query for service-level duplicate detection.

**Files:**
- Modify: `services/core-api/db/queries/cbt_questions.sql`
- Generated later: `services/core-api/internal/repository/postgres/cbt_questions.sql.go`

**Add query near create/update queries:**

```sql
-- name: GetCbtQuestionDuplicateDraft :one
SELECT *
FROM cbt_questions
WHERE event_id IS NOT DISTINCT FROM sqlc.narg(event_id)::uuid
  AND subject_id = sqlc.arg(subject_id)::uuid
  AND author_username = sqlc.arg(author_username)::text
  AND question_type = sqlc.arg(question_type)::text
  AND status = 'draft'
  AND workflow_status = 'draft'
  AND COALESCE(target_level, '') = COALESCE(sqlc.arg(target_level)::text, '')
  AND regexp_replace(lower(btrim(question_text)), '\s+', ' ', 'g') = regexp_replace(lower(btrim(sqlc.arg(question_text)::text)), '\s+', ' ', 'g')
ORDER BY updated_at DESC, created_at DESC
LIMIT 1;
```

**Notes:**
- Use `event_id IS NOT DISTINCT FROM` so `NULL = NULL` works for global bank soal.
- Keep detection limited to `status='draft' AND workflow_status='draft'` to avoid blocking legitimate revision/published flows.
- Do not create a unique index yet; text normalization with expression index can be added later after cleanup.

## Sprint 4: Cleanup Plan for Existing Duplicates (Approval Required)

### Task 4.1: Produce report-only SQL of rows to keep/delete

**Objective:** Let operator review exactly which rows would be removed.

**Policy:** Keep newest row per duplicate group; delete older rows only if unused.

**Report SQL:**

```sql
WITH ranked AS (
  SELECT q.id, q.subject_id, s.code AS subject_code, s.name AS subject_name,
         q.author_username, q.question_type, q.status, q.workflow_status,
         COALESCE(q.target_level,'') AS target_level,
         regexp_replace(lower(btrim(q.question_text)), '\s+', ' ', 'g') AS norm_text,
         q.question_text, q.created_at, q.updated_at,
         (SELECT count(*) FROM cbt_package_questions pq WHERE pq.question_id = q.id) AS package_refs,
         (SELECT count(*) FROM cbt_student_answers sa WHERE sa.question_id = q.id) AS answer_refs,
         row_number() OVER (
           PARTITION BY q.subject_id, q.author_username, q.question_type, q.status, q.workflow_status,
                        COALESCE(q.target_level,''), regexp_replace(lower(btrim(q.question_text)), '\s+', ' ', 'g')
           ORDER BY q.updated_at DESC, q.created_at DESC, q.id DESC
         ) AS rn,
         count(*) OVER (
           PARTITION BY q.subject_id, q.author_username, q.question_type, q.status, q.workflow_status,
                        COALESCE(q.target_level,''), regexp_replace(lower(btrim(q.question_text)), '\s+', ' ', 'g')
         ) AS group_count
  FROM cbt_questions q
  JOIN subjects s ON s.id = q.subject_id
  WHERE q.status = 'draft'
    AND q.workflow_status = 'draft'
)
SELECT CASE WHEN rn = 1 THEN 'KEEP' ELSE 'DELETE_CANDIDATE' END AS action,
       group_count, subject_code, subject_name, author_username, question_type,
       target_level, created_at, updated_at, package_refs, answer_refs,
       left(question_text, 120) AS preview, id
FROM ranked
WHERE group_count > 1
ORDER BY subject_code, author_username, question_type, norm_text, rn;
```

### Task 4.3: Delete only unused older duplicates

**Objective:** Remove duplicate draft records while preserving newest row.

**Delete SQL pattern:**

```sql
BEGIN;

WITH ranked AS (
  SELECT q.id,
         row_number() OVER (
           PARTITION BY q.subject_id, q.author_username, q.question_type, q.status, q.workflow_status,
                        COALESCE(q.target_level,''), regexp_replace(lower(btrim(q.question_text)), '\s+', ' ', 'g')
           ORDER BY q.updated_at DESC, q.created_at DESC, q.id DESC
         ) AS rn,
         count(*) OVER (
           PARTITION BY q.subject_id, q.author_username, q.question_type, q.status, q.workflow_status,
                        COALESCE(q.target_level,''), regexp_replace(lower(btrim(q.question_text)), '\s+', ' ', 'g')
         ) AS group_count,
         (SELECT count(*) FROM cbt_package_questions pq WHERE pq.question_id = q.id) AS package_refs,
         (SELECT count(*) FROM cbt_student_answers sa WHERE sa.question_id = q.id) AS answer_refs
  FROM cbt_questions q
  WHERE q.status = 'draft'
    AND q.workflow_status = 'draft'
), candidates AS (
  SELECT id FROM ranked
  WHERE group_count > 1
    AND rn > 1
    AND package_refs = 0
    AND answer_refs = 0
)
-- backup candidates first, then delete
INSERT INTO cbt_questions_duplicate_cleanup_backup_20260516
SELECT q.* FROM cbt_questions q JOIN candidates c ON c.id = q.id;

DELETE FROM cbt_questions q
USING candidates c
WHERE q.id = c.id;

-- Verify affected rows manually before COMMIT.
ROLLBACK;
```

**Important:** First run with `ROLLBACK`; only change to `COMMIT` after approval and verification.

## Risks / Tradeoffs

| Risk | Mitigation |
|---|---|
| Legitimate similar questions blocked | Limit guard to exact normalized text + same author/mapel/type/level + draft/draft only. Intentional duplicate button remains available. |
| Race condition if two POSTs arrive at exactly same time | Service check reduces most cases. If still observed, add transaction-level advisory lock or unique expression index after cleanup. |
| Returning existing row may surprise frontend | Treat as idempotent save; frontend only needs an ID and success state. |
| Existing duplicate cleanup deletes wrong row | Report-only first; keep newest; never delete used questions; backup candidate rows before COMMIT. |
| Workflow create/revision affected | Guard applies only normal draft create, not `/duplicate`, `/revision`, published, approved, or review workflow rows. |

## Implementation Review Update — 2026-05-16

Status setelah review ulang terhadap commit hotfix `bda70d4`:

- Patch awal sudah benar sebagai mitigasi cepat, tetapi belum cukup kuat untuk jangka panjang.
- Review menemukan 3 risiko utama:
  1. Submit review yang dipanggil ulang pada status `review/submitted` tidak boleh menurunkan status kembali ke `submitted` atau menghapus reviewer.
  2. Deteksi duplicate draft harus atomic; `SELECT` lalu `INSERT` tanpa lock masih rawan race condition jika dua POST paralel masuk sangat bersamaan.
  3. Fingerprint duplicate tidak boleh terlalu sempit; draft dengan teks/opsi sama tetapi metadata berbeda tidak boleh dianggap duplicate.

### Sinkronisasi Patch Setelah Review

Perubahan tambahan yang disinkronkan dengan plan:

1. Backend duplicate guard diperkuat dengan transaction-scoped advisory lock:
   - Query baru: `AcquireCbtQuestionDraftDuplicateLock`.
   - Lock key dibuat dari fingerprint payload draft.
   - Tujuan: mencegah dua create paralel melewati celah `SELECT` sebelum `INSERT`.

2. Fingerprint duplicate diperluas agar lebih aman:
   - Tidak hanya `question_text`, `answer_key`, dan `options`.
   - Ikut membandingkan `code`, `stem_latex`, `stimulus_html`, `stimulus_latex`, `explanation`, `explanation_html`, `rubric_html`, `difficulty`, `academic_phase`, `cp/tp/kd/indicator`, `material_topic`, `cognitive_level`, `hots_flag`, `media_asset_ids`, dan `workflow_status`.
   - Tujuan: draft yang sengaja berbeda metadata tetap tersimpan sebagai soal baru.

3. Workflow submit review dibuat idempotent:
   - Jika status sudah `submitted` atau `review`, service langsung mengembalikan row saat ini tanpa mutasi ulang.
   - Tidak ada audit event ganda.
   - Tidak mengosongkan `reviewer_username` saat status sudah masuk review.

4. Test coverage ditambah:
   - `TestCbtQuestionCreateReturnsRecentDuplicateDraftWithoutInsert`.
   - `TestCbtQuestionCreateDoesNotCollapseDifferentMetadataDraft`.
