# Plan: Lanjutkan Penyederhanaan UX CBT 3 Fase

## Tujuan
Melanjutkan implementasi UX CBT berbasis pekerjaan dengan 3 fase utama:

1. `Persiapan`
2. `Pelaksanaan`
3. `Hasil`

Fokus tahap ini adalah menyelesaikan blocking issue yang ditemukan dari validasi terakhir, menjaga halaman tetap sederhana, dan memastikan user tidak diarahkan ke route yang tidak boleh diakses oleh rolenya.

## Kondisi Terakhir
Validasi terakhir menemukan 4 blocking issue:

1. `/cbt/hasil/+page.svelte` gagal `npm run check` karena `resolve(path.href)` menerima `string`, bukan typed route literal.
2. `/cbt/persiapan` tampil untuk `guru`, tetapi berisi link admin-only seperti `/cbt/packages`, `/cbt/events`, `/cbt/sessions`.
3. `/cbt/pelaksanaan` tampil untuk `guru` dan `staf`, tetapi berisi link admin-only seperti `/cbt/sessions` dan `/cbt/events`.
4. `/cbt/hasil` tampil untuk `guru`, tetapi semua kartu mengarah ke route admin-only `/cbt/events` atau `/cbt/sessions`.

Tidak ditemukan issue pada komposer; komposer tetap tidak disentuh.

## Prinsip Implementasi

- UI-only, tidak mengubah backend/API.
- Tidak menyentuh internals Komposer Soal (`/cbt/soal`).
- Tidak menjalankan unit test, sesuai instruksi user sebelumnya.
- Jalankan validasi ringan: `git diff --check` dan `npm run check` bila diminta/feasible setelah implementasi.
- Gunakan role yang benar-benar ada: `admin`, `guru`, `staf`, `kesiswaan`, `siswa`, `ortu`.
- Jangan memakai `reviewer` sebagai role global.

## Rencana Perbaikan

### 1. Perbaiki typed route di `/cbt/hasil`

File:
- `apps/web-admin/src/routes/cbt/hasil/+page.svelte`

Masalah:
- `ResultPath.href` bertipe `string`, lalu dipakai di `resolve(path.href)`.

Perbaikan:
- Ganti tipe `href` menjadi union route literal, misalnya:
  - `type ResultRoute = '/cbt/events' | '/cbt/sessions' | '/cbt/soal';`
- Atau hindari loop dynamic untuk href dan pakai cabang statis seperti yang sebelumnya berhasil:
  - `resolve('/cbt/events')`
  - `resolve('/cbt/sessions')`
- Jika link membutuhkan query/hash, append string setelah `resolve('/route')`.

Kriteria selesai:
- `npm run check` tidak lagi gagal di `/cbt/hasil`.

### 2. Buat `/cbt/persiapan` role-aware

File:
- `apps/web-admin/src/routes/cbt/persiapan/+page.svelte`

Masalah:
- Page terlihat oleh `guru`, tetapi menampilkan link admin-only.

Perbaikan UX:
- Tetap boleh menampilkan `/cbt/persiapan` untuk `admin` dan `guru`, tetapi kartu harus disesuaikan berdasarkan role.

Untuk `admin`, tampilkan:
- `Buat Soal` -> `/cbt/soal`
- `Susun Paket` -> `/cbt/packages`
- `Buat Kegiatan` -> `/cbt/events`
- `Atur Sesi/Token` -> `/cbt/sessions`

Untuk `guru`, tampilkan hanya route yang aman:
- `Buat Soal` -> `/cbt/soal`
- `Review Soal` -> `/cbt/soal/review`
- `Lihat Hasil` -> `/cbt/hasil`

Untuk role lain:
- Tampilkan `Akses terbatas` atau arahkan ke `/cbt`.

Kriteria selesai:
- Guru tidak lagi melihat CTA ke `/cbt/packages`, `/cbt/events`, atau `/cbt/sessions`.
- Admin tetap melihat seluruh persiapan operasional.

### 3. Buat `/cbt/pelaksanaan` role-aware

File:
- `apps/web-admin/src/routes/cbt/pelaksanaan/+page.svelte`

Masalah:
- Page terlihat untuk `guru`/`staf`, tetapi ada link admin-only.

Perbaikan UX:

Untuk `admin`, tampilkan:
- `Pantau Sesi Hari Ini` -> `/cbt/sessions?schedule=today`
- `Dashboard Ruang` -> `/cbt/proctoring/rooms`
- `Panduan BYOD` -> `/cbt/byod`
- `Cetak Kartu via Kegiatan` -> `/cbt/events`

Untuk `guru` dan `staf`, tampilkan hanya route yang aman:
- `Dashboard Ruang` -> `/cbt/proctoring/rooms`
- `Panduan BYOD` -> `/cbt/byod`
- `Status Guide` -> `/cbt/byod` atau anchor yang ada

Jika `/cbt/proctoring/rooms` ternyata tidak sesuai untuk guru/staf secara route guard, gunakan `/cbt/byod` sebagai entry utama dan sebutkan dashboard ruang sebagai tautan dari sana.

Kriteria selesai:
- Guru/staf tidak melihat CTA langsung ke `/cbt/sessions` atau `/cbt/events`.
- Admin tetap melihat aksi operasional lengkap.

### 4. Buat `/cbt/hasil` role-aware dan jujur secara akses

File:
- `apps/web-admin/src/routes/cbt/hasil/+page.svelte`

Masalah:
- Guru melihat semua kartu, tetapi link mengarah ke route admin-only.

Perbaikan UX:

Untuk `admin`, tampilkan:
- `Hasil Kegiatan` -> `/cbt/events`
- `Hasil Sesi` -> `/cbt/sessions`
- `Analisis Soal` -> `/cbt/sessions`

Untuk `guru`, jangan arahkan ke route admin-only. Pilihan aman:
- `Bank Soal & Review` -> `/cbt/soal`
- `Pantau/Hasil yang tersedia` -> `/cbt/byod` atau halaman hasil guru jika route aman tersedia
- Jika belum ada route hasil guru yang aman, tampilkan copy jujur:
  - “Rekap hasil guru tersedia melalui sesi/kegiatan yang dibuka oleh admin. Saat ini halaman ini menjadi pintu informasi, bukan rekap data langsung.”
  - CTA: `Kembali ke Dashboard CBT` -> `/cbt`

Catatan:
- Jangan membuat link palsu ke admin-only route untuk guru.
- Bila ingin tetap ada `Hasil` untuk guru, page harus menjadi landing informatif sampai route hasil guru benar-benar tersedia.

Kriteria selesai:
- Admin dapat melihat 3 kartu hasil operasional.
- Guru tidak diarahkan ke route admin-only.
- Copy tetap jelas dan tidak membingungkan.

### 5. Sidebar tetap sederhana

File:
- `apps/web-admin/src/lib/components/sidebar/sidebar-config.ts`
- `apps/web-admin/src/lib/components/sidebar/sidebar-config.test.ts`

Kondisi sekarang sudah sesuai konsep:
- `Dashboard CBT` -> `/cbt`
- `Persiapan` -> `/cbt/persiapan`
- `Pelaksanaan` -> `/cbt/pelaksanaan`
- `Hasil` -> `/cbt/hasil`

Rekomendasi:
- Pertahankan 4 item ini.
- Jangan tambahkan kembali Bank Soal/Paket/Kegiatan teknis di sidebar.
- Pastikan role visibility selaras dengan role-aware page content:
  - Dashboard: `admin`, `guru`, `staf`
  - Persiapan: `admin`, `guru`
  - Pelaksanaan: `admin`, `guru`, `staf`
  - Hasil: `admin`, `guru`

### 6. Validasi Akhir

Setelah implementasi:

1. Jalankan `git diff --check`.
2. Jalankan `npm run check` di `apps/web-admin` jika feasible.
3. Tidak menjalankan unit test kecuali user meminta.
4. Sanity manual cepat:
   - Admin `/cbt` melihat: Siapkan Ujian, Atur Sesi & Token, Pantau Ujian, Lihat Hasil.
   - Guru `/cbt` melihat: Buat Soal, Review Soal, Lihat Hasil/info hasil.
   - Staf `/cbt` melihat: Pantau Ujian/Panduan BYOD.
   - Guru tidak melihat CTA ke route admin-only di `/cbt/persiapan`, `/cbt/pelaksanaan`, `/cbt/hasil`.

## Risiko dan Mitigasi

### Risiko 1: Guru belum punya route hasil yang benar-benar aman
Mitigasi:
- Buat `/cbt/hasil` untuk guru sebagai landing informatif dulu, bukan rekap palsu.
- Jangan link ke `/cbt/events` atau `/cbt/sessions` untuk guru.

### Risiko 2: Page-local guard hanya UI, bukan security boundary
Mitigasi:
- Karena spoke page tidak memuat data sensitif, page-local guard cukup untuk UX.
- Sensitive data tetap dilindungi oleh route/API guard yang sudah ada.

### Risiko 3: Terlalu banyak redirect/akses terbatas terasa mengganggu
Mitigasi:
- Jangan tampilkan CTA yang akan 403.
- Role-aware card list harus menyembunyikan pilihan yang tidak relevan.

## Hasil yang Diharapkan

Setelah rencana ini dieksekusi, CBT akan terasa lebih sederhana:

- Sidebar hanya fase pekerjaan besar.
- Dashboard `/cbt` berbasis tugas dan role.
- Persiapan/Pelaksanaan/Hasil tidak lagi memunculkan link yang membuat user tersesat.
- Komposer tetap legacy dan tidak berubah.
